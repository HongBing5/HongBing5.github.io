## 画廊图片大小写 404 修复（已改配置）
- 现象：`/masonry/` 页 photo1、photo2 在线上打不开，本地能看。
- 根因：实际文件 `photo1.JPG`/`photo2.JPG`（大写），但 `source/_data/masonry.yml` 引用是小写 `.jpg`；GitHub Pages(Linux) 大小写敏感 → 404。photo3/4 本就是小写所以正常。
- 修法：把 masonry.yml 里 photo1/2 的引用改为 `.JPG` 与实际文件一致（未重命名文件，规避 git 在 Windows 的大小写重命名坑）。
- 待用户 `hexo g && hexo d` 部署后线上验证。
- 教训：往后新增图片资源统一用全小写文件名，避免此类大小写坑。
